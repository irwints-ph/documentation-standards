🤝 Assisted Flow of Knowledge (AFK)

Understand first. Build second. Learn always.

Status

🚧 Research & Validation

Purpose

Assisted Flow of Knowledge (AFK) is an emerging methodology for AI-assisted engineering collaboration.

Rather than using AI simply to generate answers or produce code, AFK focuses on helping engineers understand, learn, discover, and preserve engineering knowledge.

The objective is not faster code generation.

The objective is better engineers through better understanding.

Vision

Create an engineering workflow where every task contributes to long-term knowledge rather than temporary output.

Every investigation...

Every bug...

Every architecture review...

Every modernization effort...

becomes an opportunity to strengthen both the engineer and the organization.

Core Philosophy

AFK begins with a simple observation:

Engineering is not the act of writing code.

Engineering is the act of understanding systems.

Code is often the final output.

Understanding is the real product.

AI-Assisted Collaboration

AFK promotes a partnership between engineers and AI.

The engineer provides:

  • context,
  • experience,
  • judgment,
  • validation,
  • decision making.

The AI contributes:

  • organization,
  • exploration,
  • synthesis,
  • documentation,
  • continuity,
  • pattern recognition.

Neither replaces the other.

Together they accelerate learning.

The AFK Mindset

AFK encourages engineers to ask different questions.

Instead of:

"How do I fix this?"

Ask:

"What is this teaching me about the system?"

Instead of:

"What code should I write?"

Ask:

"What knowledge should we preserve?"

Instead of:

"Who made the mistake?"

Ask:

"How can we improve the system so this becomes less likely?"

Canon Events

Every engineering career has defining moments.

A difficult production outage.

A legacy system that nobody understands.

An architecture decision that suddenly makes sense.

A bug that reveals a hidden design flaw.

AFK refers to these moments as Engineering Canon Events.

They are not merely incidents to resolve.

They are opportunities to learn.

Every Canon Event is a chance to extract knowledge that can strengthen future engineering decisions.

Engineering Challenges

AFK encourages viewing engineering work differently.

A bug is no longer simply something to eliminate.

It becomes an opportunity to understand the system.

An outage becomes an opportunity to improve resilience.

A difficult legacy application becomes an opportunity to preserve decades of engineering knowledge.

Every challenge contains knowledge waiting to be discovered.

Session Continuity

Engineering understanding should survive beyond a single conversation.

AFK promotes preserving context through structured artifacts such as:

  • Where We Are Now
  • Discovery Plans
  • Architecture Findings
  • Component Documentation
  • Engineering Standards
  • Knowledge Packages

This allows engineers—and AI—to resume work quickly without rebuilding context from memory.

Relationship to EDS

The Engineering Documentation System provides the standards used to document engineering knowledge.

AFK provides the methodology that guides how that knowledge is discovered and captured.

Relationship to EKS

The Engineering Knowledge System explores how engineering knowledge evolves.

AFK represents one practical methodology within that broader vision.

Current Validation

AFK is currently being validated through multiple real-world engineering activities, including:

  • legacy application discovery,
  • architecture documentation,
  • engineering standards development,
  • repository organization,
  • AI-assisted documentation,
  • engineering knowledge preservation.

Each completed activity provides evidence that shapes the methodology.

Long-Term Goal

AFK aims to make engineering knowledge easier to:

  • discover,
  • understand,
  • preserve,
  • transfer,
  • validate,
  • and continuously improve.

The success of AFK will not be measured by how much code AI generates.

It will be measured by how much understanding engineers gain.

The AFK Principle

The deliberate act of stepping away from implementation long enough to preserve understanding.

Sometimes the fastest way forward is to stop typing.

Observe.

Then continue.
