## The Canon Event

Every engineering methodology begins with a problem.

Ours began with a frontend project.

The original objective was simple:

> **Document an existing frontend application before making changes.**

The application had grown over many years.

Its architecture lived mostly inside the source code.

Like many mature systems, it worked—but understanding **why** it worked required reverse engineering.

The initial expectation was that we would simply produce documentation.

Instead, something unexpected happened.

Each question uncovered another question.

Each document exposed another missing standard.

Each architectural observation suggested a repeatable process.

The work stopped being about documenting one application.

It became about understanding **how engineers discover knowledge**.

That moment changed the direction of the project.

It was the framework's **canon event**.

---

From that point forward, the work evolved naturally.

```text
Need to document a frontend
                │
                ▼
Software Discovery
                │
                ▼
Documentation Framework

                ▼
Engineering Documentation System
                │
                ▼
Engineering Standards
                │
                ▼
Engineering Knowledge System
                │
                ▼
AFK
Assisted Flow of Knowledge
```
