# Purpose

Defines the high-level philosophy for documenting an existing software system.

Unlike greenfield documentation, discovery begins with an implementation that already exists.

The objective is to understand the system before attempting to improve or standardize it.

---

# Principles

Discovery is observational.

Discovery is implementation-first.

Discovery is evidence-driven.

Discovery avoids premature recommendations.

Discovery records existing behavior before proposing future architecture.

---

# Discovery Outcomes

A discovery effort should produce:

- System inventory
- Component documentation
- Architecture findings
- Repository observations
- Configuration documentation
- Candidate engineering standards

---

# Philosophy

Understand first.

Document second.

Improve later.
