# Purpose

Defines how engineering documentation is organized.

Documentation should be grouped by knowledge domain rather than by source code location.

---

# Current Taxonomy

## Architecture

Describes architectural concepts and discovered patterns.

Examples:

- Architecture Findings
- Composition Patterns

---

## Configuration

Documents application configuration.

Examples:

- Environment Variables
- Vite Configuration

---

## UI

Documents reusable user interface composition.

Examples:

- Layout
- Header
- Sidebar

---

## Registry

Documents the implementation inventory.

Examples:

- Folder validation
- Component documentation
- Current repository structure

---

# Philosophy

Documentation should help engineers answer questions.

It should not simply mirror the repository tree.
