# 🔍 AFK Discovery

> **Understand the system before changing the system.**

---

## Purpose

Discovery is the first engineering activity performed after a Wish has been defined.

Its purpose is to build an accurate understanding of the current system before implementation begins.

Discovery is not planning.

Discovery is not design.

Discovery is not implementation.

Discovery is understanding.

---

# Objective

Produce an accurate representation of the current system.

The goal is to answer questions such as:

- What exists?
- How is it organized?
- Why was it built this way?
- What responsibilities exist?
- What relationships exist?
- What is still unknown?

---

# Guiding Principles

Discovery should:

- observe before judging
- understand before proposing
- document before modifying
- validate before planning

---

# Inputs

Discovery typically begins with:

- Wish
- Project Context
- Existing source material
- Existing documentation
- WWAN (if available)

---

# Outputs

A completed Discovery should produce:

- Component inventory
- Responsibilities
- Relationships
- Findings
- Unknowns
- Discovery documentation

Once validated, Discovery authorizes production of:

- Grant Strategy
- Initial Architecture
- Build Plan

---

# What Discovery Is Not

Discovery is not:

- refactoring
- redesign
- optimization
- implementation
- architecture replacement

Those activities belong to Build.

---

# Validation

Discovery is complete when the current system is accurately represented.

Validation asks:

- Does this reflect reality?
- Are assumptions identified?
- Are unknowns documented?
- Is the engineering team confident enough to begin planning?

Only after Discovery has been validated should Grant begin.

---

# Relationship to AFK

```text
Wish

↓

Discovery

↓

Grant

↓

Build

↓

Observation

↓

Next Wish
```

Discovery transforms curiosity into understanding.

Grant transforms understanding into engineering intent.
