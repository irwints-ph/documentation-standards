# Documentation Organization

## Status

🚧 Draft

---

# Purpose

Defines the organizational philosophy used by engineering documentation.

---

# Principle

Documentation is organized around engineering concerns rather than source code folders.

---

# Example

Instead of:

docs/

    app/

    layout/

    routing/

    contexts/

Organize as:

Architecture/

Configuration/

UI/

Registry/

Authentication/

Routing/

---

# Benefits

- Easier navigation
- Better architectural visibility
- Supports cross-cutting concerns
- Reduces duplication
- Encourages knowledge reuse

---

# Observation

The documentation structure may intentionally differ from the implementation structure.

This is considered a feature rather than a discrepancy.
