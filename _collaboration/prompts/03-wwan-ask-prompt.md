# Where We Are Now (WWAN) Request Prompt

Thank you. Can you prepare the **Where We Are Now (WWAN)** document before we proceed to the next stage.

Please follow the WWAN standard:

`https://github.com/irwints-ph/documentation-standards/blob/main/afk/docs/collaboration/001-understanding-wwan.md`

---

# Instructions

Generate the WWAN using the current WWAN standard.

The WWAN is an **operational engineering dashboard**, not a report.

It should communicate the current engineering state clearly and concisely.

The document should summarize:

* Current status
* Current focus
* Completed milestones
* Current state
* Next milestone
* Planned next activities
* Reflection (when appropriate)

Reference completed artifacts where appropriate rather than reproducing their contents.

---

# Strict Template Compliance

Follow the WWAN structure defined in the standard.

Do **not**:

* introduce additional major headings,
* reorganize the document,
* create executive summaries,
* create architecture summaries,
* create documentation inventories,
* create project status reports.

The WWAN should remain an operational dashboard.

---

# WWAN Is NOT

The WWAN is **not**:

* Architecture documentation
* Engineering Replay
* Changelog
* Meeting minutes
* Documentation inventory
* Project history
* Technical implementation report

Those artifacts already exist independently.

The WWAN should summarize only the current engineering state.

---

# WWAN Is

The WWAN is:

* Engineering alignment
* Operational checkpoint
* Current engineering dashboard
* Synchronization artifact
* Starting point for the next engineering session

---

# Clarification Rule

Before generating the final WWAN, verify that the following are unambiguous:

* Current milestone
* Current focus
* Completion status
* Current engineering state
* Next milestone
* Planned next activity

If any of these are unclear:

* Pause.
* Ask concise clarification questions.
* Do **not** infer or invent project status, milestones, or future direction.

The WWAN should always reflect the agreed engineering state at the moment it is produced.

---

# Brevity Rule

The WWAN should remain concise.

It should fit comfortably within a single GitHub page without excessive scrolling.

If additional explanation appears necessary:

* Summarize it.
* Reference the supporting artifact instead of duplicating its contents.

---

# Output

Produce a complete WWAN document following the approved WWAN structure.

The resulting document should be suitable for immediate inclusion in the repository without structural modification.
