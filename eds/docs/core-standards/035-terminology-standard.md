# 📖 Documentation Terminology Reference

> **Consistent language creates consistent thinking.**

---

# Purpose

This document explains the philosophy, rationale, and evolution of the Engineering Documentation System's terminology.

While the companion Standard defines the preferred engineering vocabulary, this Reference explains why that vocabulary exists, how it has evolved, and the principles that guide future terminology decisions.

---

# Background

Engineering is fundamentally a communication activity.

Software changes quickly.

Knowledge changes more slowly.

Language connects both.

When teams use different words for the same concept, confusion gradually replaces understanding.

Examples include:

- Standard vs Canonical
- Feature vs Capability
- Screen vs Page
- Issue vs Bug vs Defect

Although each term may be technically correct, inconsistent usage creates unnecessary cognitive overhead.

The Engineering Documentation System promotes a shared engineering vocabulary that improves collaboration between:

- engineers,
- business stakeholders,
- AI collaborators,
- future maintainers.

---

# Philosophy

The Engineering Documentation System follows a simple principle:

> **One concept should have one preferred name.**

This does not mean alternative terminology is incorrect.

It means documentation should consistently choose one preferred term so that readers do not need to mentally translate between multiple expressions.

Consistency improves understanding.

---

# Why Standardize Terminology?

A shared vocabulary provides several long-term benefits.

It improves:

- readability,
- onboarding,
- searchability,
- documentation consistency,
- AI context quality,
- organizational knowledge transfer.

When terminology remains stable, engineering discussions become more about ideas and less about interpretation.

---

# Engineering Language Evolves

Engineering terminology is not fixed.

As methodologies mature, language naturally evolves.

The Engineering Documentation System intentionally allows terminology to improve over time through practical engineering experience.

For example, earlier versions of the framework used:

- Official Standard
- Canonical
- Companion Guide

As the ecosystem evolved, simpler terminology emerged:

- Standard
- Reference
- Quick Reference

These newer terms better communicate purpose while remaining accessible to engineers with different backgrounds.

---

# Relationship to AFK

The Assisted Flow of Knowledge (AFK) methodology places significant emphasis on shared understanding.

Rather than assuming common language already exists, AFK encourages collaborators to establish and preserve a shared vocabulary.

This terminology standard provides that common language.

It reduces ambiguity before engineering work begins.

---

# Relationship to EKS

The Engineering Knowledge System studies how engineering knowledge evolves.

Language plays a central role in that evolution.

Terminology influences:

- how engineers think,
- how knowledge is organized,
- how concepts are taught,
- how engineering practices spread across organizations.

Consistent terminology strengthens organizational knowledge by making engineering concepts easier to discover and reuse.

---

# Relationship to Documentation

Documentation serves two audiences:

- Humans
- AI collaborators

Both benefit from consistent terminology.

Humans recognize concepts more quickly.

AI systems produce more reliable summaries, classifications, and recommendations when terminology remains stable.

This consistency improves long-term collaboration without requiring project-specific vocabulary.

# The Three-Document Model

The Documentation Terminology Standard follows the Engineering Documentation System's three-document structure.

## 📘 Standard

Defines the preferred engineering terminology.

Answers:

- Which terms should be used?
- Which terms are preferred?

---

## 📖 Reference *(this document)*

Explains the reasoning behind the terminology.

Answers:

- Why were these terms chosen?
- How has the terminology evolved?
- When should terminology change?

---

## 📋 Quick Reference

Provides a concise lookup guide for everyday documentation work.

Supports engineers during writing without requiring them to read the full Reference.

---

# When Should Terminology Change?

Terminology should evolve only when there is a clear engineering benefit.

Changes should improve:

- clarity,
- consistency,
- usability,
- communication.

Terminology should **not** change simply because a new synonym becomes popular.

Stability is itself a valuable engineering property.

---

# Legacy Terminology

Historical documents may contain terminology that is no longer preferred.

Examples include:

| Historical | Preferred |
|------------|-----------|
| Canonical | Standard |
| Official Standard | Standard |
| Companion Guide | Quick Reference |

Historical terminology should generally be preserved when discussing engineering history.

New documentation should adopt the preferred terminology defined by the Standard.

---

# Frequently Asked Questions

## Why standardize terminology?

Because documentation is a long-term engineering asset.

Shared language reduces confusion and improves collaboration.

---

## Does this prohibit other terminology?

No.

Alternative terminology may still appear when discussing:

- external frameworks,
- academic literature,
- existing software,
- historical documentation.

The Standard simply defines the preferred vocabulary for Engineering Documentation System artifacts.

---

## Why change terminology over time?

Engineering practices improve.

Language should improve with them.

Changes should always be deliberate, evidence-based, and documented.

---

# Engineering Philosophy

Good engineering documentation is not only about preserving information.

It is about preserving understanding.

Shared terminology allows knowledge to move more easily between people, projects, and organizations.

Consistent language becomes part of the engineering culture.
