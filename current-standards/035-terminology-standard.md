# Purpose

Define the official terminology used throughout the Engineering Documentation System.

Using consistent terminology improves communication, reduces ambiguity, and ensures that documentation remains understandable across projects, engineering teams, business stakeholders, and AI assistants.

---

# Standard

## Use Standard Terminology

Documentation shall use the standardized terms defined by this document.

Where multiple terms exist for the same concept, one term shall be designated as the preferred engineering term.

---

## Business and Engineering Terms

Some concepts are described differently by business users and engineers.

Where appropriate, documentation should recognize both terms while clearly identifying the preferred engineering terminology.

Example

| Business Term | Engineering Term |
|--------------|------------------|
| Feature | Capability |
| Screen | Page / View |
| Customer | User |
| Issue | Defect / Bug |

---

## Preferred Terminology

The following terms are the preferred terms within the Engineering Documentation System.

| Preferred Term | Notes |
|----------------|------|
| Official | Current published engineering standard |
| Reference | Supporting explanation and rationale |
| Accepted | Approved but not yet published |
| Standard | Defines engineering rules |
| Session | Chronological engineering work log |
| Architecture | Significant engineering decision |
| Procedure | Step-by-step implementation guide |
| Knowledge | Conceptual explanation |
| Roadmap | Future vision and planned work |
| Template | Starting point for creating documents |

---

## Canonical Terminology

Some engineering terms remain valid but are not the preferred user-facing terminology.

| Engineering Term | Preferred User Term |
|------------------|---------------------|
| Canonical | Official |
| ADR (Architecture Decision Record) | Architecture Document |

These terms may appear when discussing engineering literature, existing tools, or historical documentation.

---

## Terminology Evolution

Terminology may evolve over time.

When a preferred term changes:

- Existing documentation should be updated when practical.
- Historical documents should remain unchanged unless corrections are required.
- The terminology standard shall be updated before adopting new terminology across repositories.

---

# Principles

- Use consistent terminology across repositories.
- Prefer clarity over technical jargon.
- Define new terms before widespread adoption.
- Recognize common business terminology where appropriate.
- Avoid multiple names for the same concept within a project.
